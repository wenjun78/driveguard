How to read this

  • Alert budget — the top 0.5% of the fleet each day is flagged; that is the list an operator works.
  • Matured — a snapshot's outcomes are known only 30 days later; recall and precision here are real, not validation numbers.
  • Reason codes — per-alert TreeSHAP contributions from the booster: why this drive, today.
  • Replay — Backblaze publishes history, so the daily job advances one data-day per real day; the fleet you see moves.

Monitoring

Drift, matured outcomes and the retraining decision.

Each monitoring run compares today's fleet to the reference sample stored with the champion (PSI), back-fills real outcomes for snapshots whose horizon has elapsed, and sets a retrain_recommended task value that gates the retrain task in the daily job.

Pipeline

Jobs, serving and the replay clock.

Deployed as a Databricks Asset Bundle on serverless compute: a one-off build job and a daily job (ingest → features → score → monitor → condition → retrain). The console reads these through the Jobs API.
